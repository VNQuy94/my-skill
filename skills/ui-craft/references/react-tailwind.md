# React + Tailwind v4 implementation

## Wiring

```css
/* src/styles/index.css (or the app's main CSS) */
@import "tailwindcss";
@import "./theme.css";   /* generated by tokens.mjs — never edit by hand */
```

`theme.css` resets Tailwind's default colors, fonts, text sizes, radii, and shadows (`--color-*: initial` …) and defines only the DESIGN.md tokens. Consequences:

- `bg-surface`, `text-ink`, `border-line`, `rounded-md`, `font-display`, `shadow-raised` exist; `bg-slate-100`, `text-sm`, `rounded-lg` (unless defined) **silently produce no CSS**. `lint_ui.mjs` reports them.
- Text styles are utilities: `type-display`, `type-body`, `type-label`… each sets family, size, line height, tracking, and weight together. Adjust weight with `font-semibold` only for inline emphasis.
- Opacity modifiers work on roles: `bg-accent/10`, `border-ink/20`.
- Dark mode needs no `dark:` classes: the roles switch underneath. Toggle with `document.documentElement.dataset.theme = 'dark' | 'light'`, or follow the system.
- Durations come from CSS variables: `duration-(--motion-fast)`, `ease-brand`.
- Arbitrary values are for layout only (`grid-cols-[14rem_1fr]`, `max-w-[65ch]`), never for colors or font sizes.

Projects using shadcn/ui can keep shadcn role names in DESIGN.md (`background`, `foreground`, `primary`, `primary-foreground`, `muted-foreground`, `border`, `card`…); the checks treat them as aliases.

## Components

- One component per pattern (`Button`, `Field`, `Panel`…) with variants; screens compose them. If the project has `cva` or `tailwind-variants`, use it; otherwise a small map of variant → class string is enough.
- Variants are roles, not looks: `primary | secondary | ghost | danger`, sizes `sm | md`.
- Every interactive component covers its states:

| State | Typical classes |
|---|---|
| hover | `hover:bg-accent/90` (interactive things only) |
| keyboard focus | global `:focus-visible` ring from the theme; do not remove outlines |
| pressed | `active:translate-y-px` or a darker role |
| disabled | `disabled:opacity-50 disabled:cursor-not-allowed` plus the `disabled` attribute |
| invalid | `aria-[invalid=true]:border-danger` plus a message linked by `aria-describedby` |
| loading | a spinner or skeleton in place, the control keeps its size, `aria-busy` |
| empty | an explanation and the next action, not a blank area |
| error | what happened and how to fix it, in the interface's voice |
| open/selected | `data-[state=open]:…`, `aria-selected:…` |

- Transitions name their properties: `transition-colors duration-(--motion-fast) ease-brand`.
- Tables: `tabular-nums`, right-aligned numbers, the table scrolls in its own `overflow-x-auto` wrapper on mobile.
- Images: explicit `width`/`height` or aspect ratio, meaningful `alt`.

## Content

Build with the brief's real content. When copy is missing, write specific placeholder copy from the subject's vocabulary, and mark invented numbers, names, or quotes as placeholders. Vietnamese UI text goes through `vi-writing` (sentence case, no translationese, Vietnamese number formats). Buttons name their action ("Lưu thay đổi", not "Gửi"); the same action keeps the same word through the flow.

## Build and check

```bash
npm run build                                  # vite build → dist/
node <skill>/scripts/lint_ui.mjs src
node <skill>/scripts/lint_icons.mjs
node <skill>/scripts/shoot.mjs dist --routes /,/settings --dark
```
