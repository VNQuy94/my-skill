# Pitfalls (all observed in this repo)

| Pitfall | What happened | Prevention |
|---|---|---|
| **Example leakage** | `research` v1 used the eval topics (cron reconciliation, pgvector, minimum wage) as worked examples. Runs copied the example queries word for word, so scores measured copying, not method. | `check_leakage.py` before every run; keep examples on unrelated topics. |
| **`reasoning_extraction` safeguard** | 9 of 12 runs were blocked at the first message because the prompt asked them to write their plan/reflection/gap-check notes to a file. | Ask runs to log only facts about tool use: queries, URLs, commands, check output. `init_run.py` does this. |
| **Ambiguous assertion** | "a .gov.vn source" failed a run that cited chinhphu.vn, the official portal (not a .gov.vn domain). | Spell out what counts. If you reinterpret after seeing results, report both numbers and say so. |
| **Non-discriminating assertion** | "at most 3 searches" passed for every config, so it measured nothing. | Keep assertions some config can fail; drop or sharpen the rest next iteration. |
| **Noise mistaken for signal** | With 1 run per cell, configs differed by single assertions in both directions. | Use `--runs 3` before claiming one version beats another. Say "within noise" otherwise. |
| **Grader bias** | The grader could see config names in paths. | `blind.py` copies outputs to shuffled letters; never show `blind_mapping.json`. |
| **Unequal tooling** | Baseline without the skill had no idea which tools existed and spent effort finding them. | Put shared tooling in `tools_note` so every config gets the same sentence. |
| **Lost timing data** | Token/duration numbers only appear in the task notification. | `record_timing.py` as each notification arrives. |
| **Skill bugs found by runs** | doc-style runs found 3 real bugs (venv re-exec, list runs, bold ratio) and worked around them. | Read every `notes.md`; fix bugs before judging the skill, then rerun the affected evals. |
| **Stopping early** | A usage limit cut grading short. | Grade and report each eval as soon as its runs finish; `report.py` works on partial results. |
| **Leakage introduced by fixes** | While fixing vi-writing after grading, examples were copied from the graded outputs ("không lưu được ảnh lớn hơn 25 MB"), re-creating leakage. | Run `check_leakage.py` again after every post-grading edit. |
| **Checker blind spot** | `lint_vi.py` skipped fenced code blocks, and a proofread email delivered inside ```text was never checked, yet reported "0 errors". | When a checker reports a clean result, confirm it actually saw the content (e.g. the convention line says "–" = nothing found). |
| **Leakage from fixtures and baselines** | After ui-craft grading, a fix used the eval-3 fixture's own patterns (date column, "Gia hạn" button) as the example, and named the baseline's winning devices (price board, ticket). `check_leakage.py` compares prompts only, so it did not flag either. | Also grep the skill for fixture names and for the devices the graded outputs used before re-running. |
| **Hints in shared starting files** | The baseline's starter `package.json` was named `ui-craft-app`, and the fixture's generated files carry "Generated by ui-craft" comments. | Scan prepared projects for the skill's name (`grep -rl <skill> --exclude-dir node_modules`) before launching runs. |
| **Grading source reveals the config** | UI sources contain DESIGN.md and the skill's icon wrapper. | Grade screenshots plus neutral measurements (`deliverable` = a folder, `run_deliverable` = the project). |
